# Glyph: Vite+ migration assessment

Assessment date: 2026-09-02

Tracking issue: [#537](https://github.com/SidhuK/Glyph/issues/537)

## Conclusion

This is a moderate tooling migration, not an application rewrite. Glyph already uses the parts of the Vite ecosystem that make the migration comparatively small: Vite 8, Vitest 4.1, a single `vite.config.ts`, React, TypeScript, Tailwind's Vite plugin, and Tauri's standard Vite integration. Vite+ is documented as a global `vp` command plus a project-local `vite-plus` package, and its migration command is specifically intended to consolidate existing Vite-based projects ([getting started](https://viteplus.dev/guide/), [migration guide](https://viteplus.dev/guide/migrate)). The Rust backend, Tauri commands, React feature code, and persisted data model should not need to change.

The smallest sensible migration is roughly half to one engineering day for the mechanical work and a full validation pass. A complete Vite+ adoption, including replacing Biome with Oxlint/Oxfmt and standardizing CI and developer documentation, is more realistically one to three days, with extra time reserved for lint/format behavior differences and macOS Tauri release verification. These are estimates based on the repository inventory below, not promises from Vite+.

## Current repository shape

- `package.json` already uses Vite 8.1.4, Vitest 4.1.10, pnpm 10.28.2, React 19, TypeScript 7, and Tauri 2.
- `vite.config.ts` contains the app's Vite, React, Tailwind, alias, Tauri development-server, and Vitest setup; there is no separate `vitest.config.ts`.
- There are 520 TypeScript/TSX files (about 96k lines), 52 test files, and 53 files importing from `vitest` (including the benchmark file).
- Linting and formatting are provided by Biome 1.9.4. There is no ESLint, Prettier, lint-staged, Husky, tsup, or separate Vite/Vitest config to consolidate.
- Tauri already points at `../dist`, uses port 1420, and uses the usual `TAURI_DEV_HOST`/HMR arrangement documented by Tauri for Vite projects.

## What Vite+ changes

Vite+ consists of a global `vp` CLI plus a project-local `vite-plus` package. Its migration command updates dependencies, rewrites relevant imports, merges tool configuration into `vite.config.ts`, updates scripts, optionally configures hooks/editor/agent files, and formats changed files. The [official migration guide](https://viteplus.dev/guide/migrate) explicitly says most projects still need manual follow-up.

For a pnpm project, the [migration rules](https://viteplus.dev/guide/migrate-rules) add `vite-plus`, retain a direct Vite declaration but route it through the matching `@voidzero-dev/vite-plus-core` alias, and normally remove direct `vitest` for node-mode tests. Test imports move from `vitest` to `vite-plus/test`; module augmentation declarations are intentionally left as `vitest`.

Vite+ replaces the separate lint/format path with Oxlint/Oxfmt and puts those settings in `vite.config.ts` ([configuration](https://viteplus.dev/config/), [check guide](https://viteplus.dev/guide/check)). That is the largest non-mechanical issue for Glyph: the [current Vite+ roadmap](https://github.com/voidzero-dev/vite-plus/issues/2405) still lists “Migrate from Biome” as a future migration target, so Biome rules and formatting output should be treated as a manual conversion and review rather than assumed automatic.

## Likely file surface

### Core migration

- `package.json`: add and pin `vite-plus`; adjust scripts and likely remove direct `vitest`.
- `pnpm-workspace.yaml`: add the Vite+ `vite` alias and exact bundled Vitest override while preserving existing overrides/build policy.
- `pnpm-lock.yaml`: regenerated by the migration.
- `vite.config.ts`: change `defineConfig` to come from `vite-plus`; optionally add `lint`, `fmt`, and `check` blocks.
- 53 test/benchmark files: change ordinary Vitest imports to `vite-plus/test` if following the official migration path.

### Workflow and documentation migration

- `.github/workflows/pr-checks.yml` and `.github/workflows/tauri-release.yml`: decide whether to use `vp install/check/test/build` and whether to replace the separate Node/pnpm setup/cache blocks with the official `setup-vp` action.
- `src-tauri/tauri.conf.json`: decide whether Tauri's hooks continue to call package scripts or call `vp` directly. The existing `../dist` and port arrangement can remain.
- `README.md`, `CONTRIBUTING.md`, and `AGENTS.md`: update command, runtime, lint, formatter, and prerequisite documentation.
- If adopting Vite+ hooks: add the project-owned `.vite-hooks/pre-commit` policy and generated dispatcher setup; this is optional and should be treated separately from the core migration.

### Probably untouched

- React application and editor code, except for test imports.
- Tauri command contracts, Rust modules, SQLite/indexing code, native menus, and app data/storage.
- Tailwind, Tiptap, CodeMirror, and other application dependencies, subject to normal compatibility verification.

## Risks and verification

1. **Biome to Oxc behavior:** lint findings, formatting, import organization, and generated diffs may change. Compare the existing Biome behavior before deleting `biome.json` or `@biomejs/biome`.
2. **Vite+ toolchain alignment:** Vite+ uses Vite 8 with Rolldown, but Glyph is already on Vite 8, so this is not a second Vite 7-to-8 migration. The migration warns about patterns such as `manualChunks`, but does not rewrite them; the current config does not use one. Vite 8 itself documents the Rolldown/Oxc change and compatibility layer ([Vite 8 announcement](https://vite.dev/blog/announcing-vite8)).
3. **Command semantics:** `vp dev` and `vp build` always invoke Vite+'s built-in commands; `vp run dev` and `vp run build` invoke package scripts. This matters for Tauri's `beforeDevCommand` and `beforeBuildCommand`.
4. **Node/CI version:** Vite+ manages Node and the package manager through `vp`; the CI workflow currently pins Node 20 and pnpm 10. Keep Node at a Vite-compatible 20.19+ floor or intentionally move CI to the version selected for the Vite+ release.
5. **Tauri release path:** after frontend checks pass, validate the actual macOS Tauri dev/build/release flow because the release workflow packages the native app and updater artifacts.

The official post-migration validation is `vp install`, `vp check`, `vp test`, and `vp build`. For Glyph, add the existing Rust check and a macOS Tauri build/release smoke test.
